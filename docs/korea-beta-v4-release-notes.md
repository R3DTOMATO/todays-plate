# 오늘의 식탁 한국 친구 베타 v4 변경 기록

## 개발 목적

친구 대상 무료 베타에서 디자인 선호가 아니라 다음 핵심 가설을 측정할 수 있도록 구현 범위를 정리했다.

> 사용자가 조건 세 개를 고른 뒤 추천 메뉴를 실제 식사 결정과 기록까지 연결할 수 있는가?

## 1. 추천 흐름

- 현재 시각을 아침·점심·저녁·야식으로 자동 판정한다.
- 추천 도중 선택 조건과 현재 단계를 로컬에 저장한다.
- 12시간 안에 앱을 다시 열면 추천 또는 마지막 결과를 이어 볼 수 있다.
- 최근 3일 동안 기록한 메뉴와 현재 추천 세션에서 거절한 메뉴는 다시 추천하지 않는다.
- 후보가 부족해도 제한 조건을 자동 완화하지 않는다.
- 대표 메뉴 한 개와 대안 메뉴 최대 두 개를 표시한다.

## 2. 추천 결과 정보

- 예상 가격 범위
- 예상 준비·조리 시간
- 식사 방식
- 주요 식재료
- 매운맛
- 포만감
- 알레르기 가능 식재료
- 원재료 및 교차 오염 직접 확인 안내

알레르기와 먹지 않는 식재료는 추천 점수 감점이 아니라 후보 제외 조건으로 처리한다.

## 3. 거절 피드백

다음 이유를 저장하고 현재 추천 세션에 반영한다.

- 최근에 먹었음
- 가격이 부담됨
- 지금 먹고 싶지 않음
- 주변에서 찾기 어려움
- 조리하기 어려움
- 재료가 마음에 들지 않음
- 양이 적을 것 같음
- 양이 많을 것 같음
- 기타

양이 적거나 많다는 피드백은 포만감 조건에, 조리 부담은 짧은 조리 시간 우선순위에 반영한다. 한 번의 거절만으로 식재료를 영구 제외하지 않는다.

## 4. 식사 기록

- 날짜와 시간
- 아침·점심·저녁·야식
- 외식·배달·집밥·편의점
- 실제 지출
- 만족도
- 다시 먹고 싶은지
- 메모
- 사진

사진은 브라우저에서 축소한 뒤 로컬에 저장한다. 저장 공간이 부족하면 사진 없는 기록 보존을 우선한다.

기록 요약은 횟수·음식 종류·지출·식사 방식·새 메뉴·반복 메뉴·만족 메뉴·거절 종류처럼 입력된 사실만 표시한다.

## 5. 주변 식당

- 사용자가 주변 식당을 실행했을 때만 위치 권한을 안내한다.
- 위치 사용 목적, 일회성 검색, 비추적, 수동 입력 가능 여부를 권한 요청 전에 설명한다.
- 권한을 거부하거나 위치 확인이 실패하면 지역·주소·역 이름을 입력할 수 있다.
- 브라우저에는 Kakao REST API 키를 넣지 않는다.

## 6. 분석과 피드백

- 첫 사용 시 선택 분석 동의를 받는다.
- 동의 전 이벤트는 수집하지 않는다.
- 이벤트는 오프라인 큐에 저장했다가 서버 연결 시 재전송한다.
- 이벤트에서 이름, 연락처, 정밀 위치, 주소, 사진, 메모를 제거한다.
- 피드백도 오프라인 보관과 재전송을 지원한다.
- 사용자는 분석 동의를 변경하고 로컬 데이터를 JSON으로 내려받거나 전체 초기화할 수 있다.

## 7. 서버와 운영 리포트

추가된 API:

- `/api/health`
- `/api/nearby`
- `/api/resolve-location`
- `/api/events`
- `/api/feedback`

`server/beta-report.mjs`는 추천 퍼널, 선택률, 기록률, 거절 이유, 기능 이용률, 오류와 피드백 유형을 집계한다.

## 남은 제한

- 로그인과 다중 기기 동기화는 아직 없다.
- 식당의 실제 가격·영업시간은 Kakao 응답 범위와 운영 데이터에 의존한다.
- 음식 사진은 프로토타입 외부 URL이 포함되어 있어 정식 배포 전 사용 권한과 CDN 이전이 필요하다.
- 운영 환경의 분석·피드백 저장은 JSONL이 아니라 데이터베이스와 접근 제어로 이전해야 한다.
