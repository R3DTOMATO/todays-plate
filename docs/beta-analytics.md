# 베타 통계 운영

## 배포와 접속

1. 변경을 병합한 뒤 Railway API를 먼저 배포합니다.
2. Railway의 기존 관리자 설정 `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `ADMIN_UIDS`를 확인합니다. `ADMIN_UIDS`에는 Firebase Authentication 사용자 목록에서 확인한 관리자 UID를 쉼표로 구분해 넣습니다. 개인 키를 프런트엔드 설정에 넣지 않습니다.
3. 기존 Volume과 `DATA_DIR=/app/server/data`를 유지합니다.
4. Firebase Hosting을 배포합니다. Firestore 규칙 변경은 없습니다.
5. `https://todays-plate.web.app/admin/analytics.html`에서 관리자 계정으로 로그인합니다. 기존 신고 검토 화면에서도 이동할 수 있습니다.

통계 API는 `GET /api/admin/analytics`이며 Firebase ID 토큰과 서버의 관리자 UID 검사를 모두 통과해야 합니다. 관리자 설정 누락은 503, 인증 실패는 401, 관리자 아닌 계정은 403입니다. 응답은 캐시하지 않습니다. `/server/data`나 `GET /api/events`를 공개하는 기능은 추가하지 않습니다.

## 집계 기준

- 기본 기간은 한국 시간으로 오늘을 포함한 최근 30일이며 최대 366일입니다.
- 브라우저 수는 익명 브라우저 ID 수입니다. 실제 사람 수와 다르며 세션 수도 탭·테스트 영향을 받습니다.
- 추천 흐름마다 새 ID를 발급합니다. 기간 안에 처음 시작한 추천에 대해 종료일까지 발생한 완료 → 결과 확인 → 메뉴 결정 → 기록을 순서대로 연결합니다. 반복 클릭은 전환 수를 늘리지 않습니다.
- 완료율은 시작 대비 완료, 결정률은 결과 확인 대비 결정, 기록률은 결정 대비 기록입니다. 분모가 0이면 비율을 표시하지 않습니다. 최근 추천은 아직 후속 행동이 끝나지 않았을 수 있습니다.
- 식사 기록은 결정한 메뉴의 관련 화면에서 작성한 새 기록만 연결합니다. 메뉴와 식사 시간이 맞아야 하며 과거 날짜 기록·기록 수정은 새 전환이 아닙니다. 사용자가 입력한 기록으로 실제 식사를 독립적으로 확인한 수치는 아닙니다.
- 기존 이벤트 파일은 유지됩니다. 추천 ID가 없는 과거 이벤트는 전체 이벤트 횟수에 포함되지만 추천별 전환에는 포함되지 않습니다. 기존 129건을 새 추천 흐름으로 임의 복원하지 않습니다.
- 일별 결정은 해당 날짜에 처음 결정한 추천 수입니다. 실패·오류 표에는 위치 권한 실패도 포함하며 원문 메시지는 노출하지 않습니다. 기존 `unknown` 오류에 추정 코드를 붙이지 않습니다.
- 데이터 품질의 읽지 못한 행·잘못된 날짜 수는 읽은 전체 파일 기준입니다. 추천 ID 없는 이벤트에는 정상적인 일반 행동도 포함됩니다.

기존 분석 동의가 있어야 전송합니다. 로그인·회원가입 이전 이탈을 새로 수집하는 변경은 아닙니다. 전송 중 추가된 이벤트를 보존하고 서버가 확인한 ID만 전송 완료 처리합니다. 기존 브라우저 저장 용량 제한과 여러 탭 간 경쟁까지 해결하는 영구 메시지 큐는 아닙니다.

## 개발자 테스트 제외

관리자 화면의 ‘내 테스트 데이터 구분하기’에서 현재 브라우저의 테스트 표시를 켭니다. 같은 사이트·브라우저에서 이후 생성하는 앱 이벤트에 표시가 붙습니다. 이 설정 자체는 분석 수집 동의를 부여하지 않습니다. 기본 통계에서 표시된 이벤트는 제외되며 ‘테스트 이벤트 포함’으로 조회할 수 있습니다.

표시 전의 데이터는 ‘이 브라우저의 과거 데이터 제외’ 또는 추가 브라우저 ID 입력으로 제외합니다. 다른 기기·브라우저는 각각 설정해야 합니다. 서버 전체에 항상 적용하려면 Railway에 `ANALYTICS_EXCLUDED_IDS=브라우저ID1,브라우저ID2`를 설정합니다. 이는 Firebase UID가 아닙니다. 필터는 원본 파일을 삭제하지 않습니다.

## CLI와 검증

`npm run report`의 기존 최상위 집계는 전체 기간의 단순 횟수로 유지됩니다. 새 `linkedRecommendations` 항목은 대시보드와 같은 기간·연결 기준입니다. 둘의 분모를 섞지 마세요. CLI 기간과 필터는 `ANALYTICS_FROM`, `ANALYTICS_TO`(YYYY-MM-DD), `ANALYTICS_INCLUDE_TESTS=true`, `ANALYTICS_EXCLUDED_IDS`로 지정합니다.

집계는 기존 월별 JSONL과 과거 events.jsonl을 읽으며 이벤트 ID 중복을 제외합니다. 읽은 이벤트를 메모리에서 집계하므로 소규모 베타 용도입니다. 데이터가 커지면 집계 저장소 도입이 필요합니다.

```sh
npm run check
npm run test:analytics
```

브라우저 검증은 Python Playwright와 Chromium이 필요합니다. 별도 터미널에서 저장소 루트의 정적 서버를 실행한 다음 테스트합니다.

```sh
python -m http.server 9154 --bind 127.0.0.1
```

```sh
npm run test:analytics:ui
npm run test:entry
```

`PLATE_TEST_URL`, `PLATE_BROWSER`로 서버 주소와 브라우저 실행 파일을 지정할 수 있습니다. HTTP 권한 테스트는 로컬 테스트 키로 서명한 토큰을 사용하며 실제 인증 검증 경로를 확인합니다. 브라우저 테스트는 Firebase·통계 응답을 대체하므로 운영 계정이나 운영 데이터를 변경하지 않습니다. 실제 배포 후에는 관리자 로그인, 일반 계정 접근 차단, 동의한 테스트 이벤트 수신을 별도로 확인합니다.
